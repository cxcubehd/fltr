## What it is

A UI framework you embed in a game engine. It does not own the window, the input
system, the GPU, or the clock. You push state in, you call one function per
frame, and you get back an ordered list of drawing commands to translate.

```cpp
// Once.
MyTextService text;
fltr::WidgetBinding binding({1280, 720}, text);
binding.attachRoot([&] { return hud(state); });

// Every frame.
for (const auto& event : platformEvents) binding.dispatchPointer(event);
const fltr::Scene scene = binding.drawFrame(deltaSeconds);
submit(*scene.root);
```

A frame in which nothing changed builds nothing, lays out nothing, paints
nothing, and hands back a scene whose `revision` has not moved — so you can
resubmit last frame's translation verbatim.

## The four load-bearing ideas

Everything else in fltr is negotiable. These are not, and the whole design is
arranged around keeping them true.

<CardGrid>
  <Card title="Three trees, three lifetimes" icon="seti:cpp">
    What you write (a **widget**) is not what persists (an **element**) and not
    what lays out and paints (a **render object**). That split is what makes
    declarative authoring compatible with incremental update.
  </Card>
  <Card title="Constraints down, sizes up" icon="puzzle">
    A parent hands a child constraints; the child answers with a size. A child
    never sees its parent's size. Layout is one linear pass, not a solver.
  </Card>
  <Card title="Boundaries, not trees" icon="approve-check">
    Layout invalidation and paint invalidation are **separate** paths with
    separate dirty lists. Update cost is proportional to what changed, not to
    how big the tree is.
  </Card>
  <Card title="A gesture arena" icon="rocket">
    Overlapping interactive regions resolve deterministically, and a recognizer
    keeps receiving events after the pointer has left the region it started in.
  </Card>
</CardGrid>

## What it deliberately is not

It has no renderer, no font loader, no window, no navigator, no accessibility
tree, and no theme system. Each of those is either the consumer's job or a
recorded decision with a stated cost — and the ones that are gaps rather than
decisions are written down too.
